Background
How this differs from KaTeX and MathJax they set the formula into the page; this makes a picture of it

KaTeX and MathJax set a formula into the page. They bring their own fonts, lay it out as HTML and CSS, and what you get is live web text that reflows with the paragraph around it.

This sets the formula with a font you choose and hands you an image of it. The result is paths, not elements: the SVG needs no stylesheet, no webfont and no engine at read time. It goes wherever a picture goes — a slide, a paper, an email, a vector file for print — and it looks like the text around it if you pick a matching font.

That is also the limit. A picture does not reflow, cannot be selected or copied as an expression, and a screen reader gets the alt text instead. For math inside running text, KaTeX is the better tool; this is for math that ends up in a document.

If Copy or dragging does not work with an app, these put the image on the clipboard as
      rich text instead: HTML with the image embedded. Whether the target app keeps it as a vector image,
      converts it to a bitmap or ignores it depends on the app.

    

      
    

    
With SVG selected, Copy SVG copies the SVG source code as text, ready to paste into a
      file or an editor. With PNG selected, Copy PNG copies the image itself.
